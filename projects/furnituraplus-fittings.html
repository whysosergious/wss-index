Fifteen thousand SKUs and one man's memory

A Belarus fittings reseller whose prices, variants and stock lived in people's heads — until 15,000 SKUs moved into a store that prices, searches and syncs itself.

By Sergio Stankevich · Freelance full-stack build

The warehouse manager at FurnituraPlus could look at a hinge and tell you its angle, its mount, whether it was in stock, and what your price was — from memory. It was genuinely impressive, and it was also the entire ordering system. Trade clients ordered from PDF price lists by phone, variant codes were cryptic strings only insiders could decode, stock answers took a day, and the tier discounts lived in exactly one person's head. When that person went on holiday, the business slowed down. That's not a process; that's a hostage situation with extra steps.

So we built the boring miracle: a B2B store where a furniture maker configures a hinge visually — angle, mount, finish — sees their own tier price and live stock, and reorders in one click. Behind it, the ERP syncs stock and invoices both ways, and the search finds "that Blum thing, 110 degrees" in milliseconds across fifteen thousand rows.

The goal

Put the whole catalogue online with real variants (not cryptic codes), tiered trade pricing that matches what the sales desk would quote, live stock from the ERP, and search that forgives typos and half-remembered names. If a client can order at 11pm without calling anyone, we win.

What kept me up at night

First, impossible combinations. A hinge's angle, mount, finish and hand interact — not every combination exists, and letting a client order a phantom SKU means an embarrassing cancellation. The variant matrix only expands compatible options, so the UI physically cannot arrive at a product that doesn't exist. The configurator guides; it never apologises.

Second, two prices for one product. The moment the storefront and the ERP disagree on a tier price, trust evaporates and the phones start ringing again. So pricing is one server-side engine — tiers plus volume breaks — called by the store and mirrored into the ERP documents. Same inputs, same number, everywhere.

Third, search across 15k cryptic rows. Clients search like humans: "blum hinge 110", misspelled, partial. Trigram plus full-text search over names, codes and attributes made that instant, with a 200-millisecond budget I refused to break. A B2B store where you can't find things is just a prettier PDF.

The piece of code that saved us

The pricing engine. Bronze, silver, gold tiers with volume breaks, computed server-side in one place — the storefront calls it, the ERP mirrors it, and the "what's my price?" phone calls stopped. This is the function the whole business now runs on:

// pricing.ts — ONE engine for storefront and ERP. Same inputs, same number.
export type Tier = 'bronze' | 'silver' | 'gold';

const TIER_DISCOUNT: Record<Tier, number> = {
  bronze: 0, silver: 0.07, gold: 0.12,
};

function volumeDiscount(qty: number): number {
  if (qty >= 1000) return 0.08;
  if (qty >= 200) return 0.04;
  return 0;
}

export function tradePrice(base: number, tier: Tier, qty: number): number {
  const discounted = base * (1 - TIER_DISCOUNT[tier]) * (1 - volumeDiscount(qty));
  return Math.round(discounted * 100) / 100;
}

// Quote lines keep the receipt: every discount visible, every line auditable.
export function quoteLine(base: number, tier: Tier, qty: number) {
  return {
    unit: tradePrice(base, tier, 1),
    total: Math.round(tradePrice(base, tier, qty) * qty * 100) / 100,
    breakdown: `${tier} −${TIER_DISCOUNT[tier] * 100}% · vol(${qty}) −${volumeDiscount(qty) * 100}%`,
  };
}

The breakdown string is the quiet hero: every quote shows exactly how the price was built. Clients stopped haggling over numbers they could see being fair.

How it landed

Fifteen thousand SKUs, searchable in under 200 milliseconds. Stock that's real because the ERP says so twice a day, both directions. Reorders in one click, quotes clients can forward to their own customers. And the warehouse manager? He still knows every hinge by sight. He just doesn't have to be the database anymore — he finally took a proper holiday.

What I'd do differently

I'd add reorder predictions sooner — "you buy these slides every six weeks, you're due" — from order history. The data was there from month two; we only surfaced it much later, and it would have been the stickiest feature in the store.
