The batch that almost got away

A Stockholm microbrewery where fermentation graphs itself, stuck batches page the brewer, and the excise-tax report writes itself from the batch ledger.

The head brewer showed me his system with genuine pride: a whiteboard, three notebooks, and a spreadsheet named something like FINAL_v7_really.xlsx. Fermentation readings went on the whiteboard when someone remembered. Recipes lived in the spreadsheet. And once a year, the excise-tax report got assembled the night before the deadline from all three, with the mood you'd expect. Then one spring, a batch stalled mid-fermentation and nobody noticed for two days. That was the batch that almost got away — and the reason this project exists.

What we built is a brewery that watches itself. Gravity and temperature sensors push readings every minute into a time series. The brewer sees live fermentation curves per tank, gets paged when a batch flatlines above target, and gates packaging on QC checks. Packaged litres flow into strength bands, and the Swedish alkoholskatt report falls out of the ledger instead of out of a panic.

The goal

Track every batch from grain to glass: recipe versions you can actually diff, live fermentation monitoring, quality-control workflows before anything gets packaged, and excise reporting the tax office would accept without questions. Brewers should brew; paperwork should write itself.

What kept me up at night

First, silent stalls. A stuck fermentation doesn't announce itself — the beer just quietly stops becoming beer, and every hour of delay risks the batch. The system had to notice flatlines on its own: gravity unmoved for 24 hours while still above target means the brewer's phone buzzes, day or night. That alert is the single most valuable notification I've ever shipped.

Second, sensor data you can trust. Out-of-order points, gaps, a probe pulled for cleaning — time-series data is messy, and a pretty curve drawn from garbage is dangerous. Ingest is idempotent on batch plus timestamp, gaps get flagged instead of silently interpolated, and cleaning windows are excluded. The curve shows what happened, including the holes.

Third, the tax report. Alkoholskatt bands by strength, litres packaged, audit-ready. This couldn't be a spreadsheet export someone edits — it aggregates straight from the batch ledger, so the number on the report and the number in the system are the same number by construction.

The piece of code that saved us

The ingest plus stall-watch pair. Sensor batches land idempotently in the time series, and every ingest runs the deviation check: is gravity moving, is temperature in range, and — the critical one — has this batch flatlined above its target? That last question is what would have saved the spring batch.

// ferment.ts — ingest sensor data, watch for the stall nobody notices
export interface Reading { ts: number; sg: number; tempC: number; cleaning?: boolean }

export async function ingest(batchId: string, points: Reading[]) {
  const real = points.filter(p => !p.cleaning); // probes lie during cleaning
  const lines = real.map(p =>
    `ferment,batch=${batchId} gravity=${p.sg},temp=${p.tempC} ${p.ts * 1e9}`);
  await influx.write(lines); // idempotent on (batch, ts): replays are safe

  await checkStall(batchId);
  await checkTempRange(batchId, real);
}

async function checkStall(batchId: string) {
  const day = await influx.last24h(batchId); // gravity readings, newest last
  if (day.length < 10) return; // not enough data to judge

  const gravity = day.map(r => r.sg);
  const spread = Math.max(...gravity) - Math.min(...gravity);
  const target = await db.targetFG(batchId);

  if (spread < 0.001 && gravity[gravity.length - 1] > target) {
    await pageBrewer(batchId, `Stalled at SG ${gravity.at(-1)} (target ${target})`);
  }
}

The length < 10 guard matters more than it looks: a brand-new batch with three readings isn't stalled, it's just young. Alerting on that would have trained everyone to ignore the pager within a week.

How it landed

Sensor resolution went to one minute, and the whiteboard retired with honours. No lost batches in the year after launch — including one stall caught at 3am that would previously have been found on Monday. Excise-report prep went from a panicked evening to an export. And recipe versioning ended the FINAL_v7 era: every tweak has an author, a date and a reason.

What I'd do differently

I'd put a cheap display on each tank showing its own curve. Brewers live by the tanks, not by dashboards — the information should meet them where they stand, in the cold room, with wet hands.
